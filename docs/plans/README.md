# 計画書の管理

構成変更・移行・削除を伴う作業は、計画書の作成、方針の合意、実装・検証の順で進める。
軽微な修正や合意済み計画内の個別作業では、新しい計画書や再合意を毎回求めない。
対象範囲や削除の影響が大きく変わる場合は、変更点を提示して合意を得る。

## 保存先と命名

- 保存先: `docs/plans/`
- ファイル名: `YYYY-MM-DD-<目的を表す英語名>.ja.md`
- 日付は作成日とし、更新や状態変更でファイル名を変えない。
- 文書の冒頭に状態と作成日を記載し、合意後は合意日も記載する。
- 状態は「提案中」「合意済み」「実施中」「完了」「中止」から選ぶ。

設計上の決定と採用理由は [ADR](../adr/README.md) に残し、計画書と相互にリンクする。

## 内容と更新

計画書には目的、対象範囲、判断、作業順、完了条件を記録する。
合意後は同じ文書の状態とチェック項目を更新する。
詳細な棚卸し結果や作業ログは必要に応じて別文書に分け、計画書から参照する。
認証情報や Terraform state は保存しない。

完了・中止後も計画書は同じ場所に残す。
継続利用する運用手順は別文書に整理する。

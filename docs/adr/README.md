# ADR の管理

ADR は、将来も参照する設計上の決定とその根拠を記録する。
確定した文書すべてを ADR にする必要はない。
作業順と進捗は[計画書](../plans/README.md)、現在の操作方法は運用手順として管理する。

## 保存先と命名

- 保存先: `docs/adr/`
- ファイル名: `YYYY-MM-DD-<決定内容を表す英語名>.ja.md`
- 連番は使用せず、同日の ADR は決定内容の名前で区別する。
- 日付は作成日とし、更新や採用時にファイル名を変更しない。
- 文書内に作成日、状態、決定済みの場合は決定日を記載する。
- 状態は「提案中」「採用」「却下」「廃止」「後続 ADR により置換」から選ぶ。

## 内容と変更

背景、決定、検討した代替案、採用理由、結果・制約、関連文書を記録する。
計画書とは相互にリンクし、具体的な作業項目や進捗を二重管理しない。

採用済みの決定を覆す場合は新しい ADR を作成し、旧 ADR と相互にリンクする。
旧 ADR の状態を更新し、過去の採用理由は書き換えずに残す。
誤記の修正や説明の補足は既存 ADR で行える。
